# ISO/IEC 27001 compliance

Pezhwan ships no built-in ISO 27001 service (unlike GDPR, HIPAA, PCI, SOC 2,
and CCPA). This document maps the Annex A controls relevant to an IAM system,
shows how Pezhwan supports each, and notes what the ISMS certification process
must provide.

---

## 1. Annex A control mapping

### A.5 — Organizational controls

| Control                    | Pezhwan implementation                         | Gap                        |
| -------------------------- | ---------------------------------------------- | -------------------------- |
| A.5.1 Policy               | `docs/security/README.md`, `THREAT-MODEL.md`   | Formal ISMS policy per org |
| A.5.7 Threat intel         | Risk engine, breach detector, HIBP integration | Implemented in code        |
| A.5.15 Access              | RBAC deny-by-default, ABAC, admin gate         | Implemented in code        |
| A.5.23 Cloud info security | `SecretProvider` abstraction, trust boundaries | Deployment responsibility  |

### A.8 — Asset management

| Control               | Pezhwan implementation                         | Gap                         |
| --------------------- | ---------------------------------------------- | --------------------------- |
| A.8.4 Transfer        | TLS required, CORS allowlist, security headers | Implemented in code         |
| A.8.5 Secure deletion | GDPR erase (soft + hard purge)                 | Organization sets retention |
| A.8.9 Config mgmt     | Zod-validated env, production invariants       | Implemented in code         |
| A.8.11 Data masking   | Logger redaction, `select:false` fields        | Implemented in code         |
| A.8.12 DL Prevention  | Secret scan, CORS, CSRF, no wildcards          | Implemented in code + CI    |

### A.9 — Access control

| Control                           | Pezhwan implementation                           | Gap                 |
| --------------------------------- | ------------------------------------------------ | ------------------- |
| A.9.1 Policy                      | RBAC + ABAC deny-by-default                      | Implemented in code |
| A.9.2 Registration/deregistration | Tenant-scoped lifecycle, revocation              | Implemented in code |
| A.9.3 Privileged access           | Admin gate, time-limited elevation               | Implemented in code |
| A.9.4 Authentication              | Argon2id, MFA, risk-based auth, WebAuthn, SRP-6a | Implemented in code |

### A.10 — Cryptography

- **A.10.1 Cryptographic controls** — Argon2id, RSA-2048/RS256, SHA-256, TOTP
  in `@pezhwan/crypto`.
- **A.10.2 Key management** — KeyStore lifecycle (GENERATED → REVOKED),
  scheduled rotation, JWKS publication.
- **A.10.4 FIPS 140-2/3** — Node.js crypto; FIPS-built deployments per
  `fedramp.md`.

### A.12 — Operations security

| Control                   | Pezhwan implementation                       | Gap                        |
| ------------------------- | -------------------------------------------- | -------------------------- |
| A.12.3 Backup             | Backup verification + restore drills         | Implemented                |
| A.12.4 Logging            | Audit service, risk events, security alerts  | Implemented in code        |
| A.12.6 Vulnerability mgmt | `npm audit`, `gitleaks`, `secret-scan` in CI | Implemented in CI          |
| A.12.8 Security events    | Incident response doc, correlation IDs       | Implemented in code + docs |

### A.13 — Communications security

Security of networks (A.13.1) and information in transit (A.13.3): CORS
allowlist, security headers, TLS, and the HTTPS-issuer production invariant.

### A.14 — Secure development

Security suites, threat model, fail-closed defaults (A.14.1/14.2); test
fixtures use clearly dummy values with documented exceptions (A.14.3).

### A.16 — Incident management

A.16.1 procedures in `docs/security/incident-response.md`; A.16.2 assessment
via risk engine, decoy alerts, and audit correlation; A.16.3 runbook + key
revocation procedures.

### A.18 — Compliance

A.18.1 legal compliance via the GDPR/HIPAA/PCI/SOC 2/CCPA services; A.18.2
reviews via `scripts/security-audit.mjs` and the pen-testing methodology; A.18.3
checklist gates and CI enforcement.

## 2. ISMS process notes

Pezhwan supplies technical controls; certification additionally requires the
organization to:

1. Define ISMS scope including Pezhwan as a controlled system
2. Conduct a risk assessment mapped to Annex A
3. Produce a Statement of Applicability (implemented / partial / excluded)
4. Schedule internal audits and management reviews
5. Track nonconformities and corrective actions

## 3. Gap analysis guidance

- **Implemented in code** — verify the deployment configuration matches
- **Organization responsibility** — outside Pezhwan's scope; implement and
  document
- **CI/CD configuration** — confirm the organization's pipeline includes the
  gates
- **Documentation exists** — adopt and maintain; link into the ISMS
  document set
